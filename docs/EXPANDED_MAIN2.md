# Expanded model explorer

This branch began at `main2` commit `9f7f92d`. It preserves both earlier engines and connects the existing fully trainable 28,186-parameter NumPy transformer to the same lesson API. The browser selects that model by default; API clients that omit `engine` retain the original team model for compatibility.

## Model and trace

`POST /api/sessions` accepts `engine: "transformer"` or `engine: "team"`. Each session retains its own engine, optimizer state, training history and revision. Checkpoint restore restores the same engine family. Model switching preserves both browser-session IDs.

Transformer trace schema 5 contains both layers, both attention heads, Q/K/V projection weights and biases, normalized inputs, head outputs, projected attention, residual states, GELU intermediates, output projection weights and bias, and the final normalized representation. `selectTrace()` chooses a layer/head for display without modifying the API response. The projection view always uses the final normalized representation after both layers.

The six lesson stages group transformer operations. The attention stage includes head concatenation, attention output projection, residual addition, normalization, feed-forward expansion/GELU/contraction and a second residual addition. The inspector exposes those arrays. The 3D overview displays the selected layer/head; it does not represent every block simultaneously. Close-ups display a coordinate window and label that window. All full values remain available in the inspector.

The larger checkpoint is the existing `artifacts/tiny-transformer.npz`, trained for 1,200 steps on `data/train.txt`; `data/validation.txt` is held out. Its checkpoint report and dataset hashes remain in `artifacts/training-report.json`. Connecting it does not imply a new training run. Its corpus is small and intentionally simple, so readable fragments should not be confused with broad language competence.

## Animation and arithmetic

`OperationJourney` gives each operation a 6.4-second explanatory cycle. Scrubbing pins geometry to a chosen point in that cycle. Reduced motion shows settled values; camera controls and stage navigation remain available. Architecture mode shows actual tensors with moving connections. Operation mode focuses the character, dimension window, and selected head. Play respects the active tab: architecture mode retains its tensor-flow camera tour, while the character tab plays the detailed operation sequence. Pause stops the active animation without switching modes.

The embedding explorer evaluates scalar-weighted sums in all 768 dimensions. It projects the zero vector and each partial sum separately, preserving the centering offset of PCA. Zero-length additions keep their place in the animation timeline, and a zero result reports that cosine similarity has no defined direction. Numerical rankings continue to work without WebGL.

## Lab fixes

- Reconnecting revalidates the current session instead of deleting trained weights.
- Expired sessions are replaced with the selected engine family.
- Prompt and temperature survive navigation to and from the embedding explorer.
- A synchronous operation guard prevents overlapping training/reset/sample actions.
- The sampling panel displays probabilities beside the temperature control.
- Errors are visible inside the experiment drawer, with a retry action.
- Training instructions identify the active engine, corpus, optimizer and scope.
- Integer sampling seeds, live weight deltas, stop controls and checkpoint restoration are covered by browser regressions.
